# MindIsle 水球：Blender 视觉定稿 → 动画 → Unity 复现

```text
你是一名负责透明水体材质与实时图形移植的视觉技术美术。请在 /Users/fran/Documents/Code/mindisle/blender 中制作中央水球，先把 still 和 moving 都作为完全静止的造型完成参考图复现，再制作动画，最后提供可供 Unity 重新实现的参数与资产。当前阶段只执行静态成对画面，不提前制作动画或修改 Unity、WebGL。

1. 参考与边界
逐张查看 /Users/fran/Documents/Code/mindisle/demo-reference/still-state.png 和 motion-state.png。只参考水球、内部层次、光线、流带和背景；删除参考图中的手机状态栏、文字、时间和其他界面。已有 Blender、Unity 试验不是合格视觉基准，不能直接延续错误效果。禁止将参考图、视频或序列帧贴在画面中冒充渲染；参考图只能用于工作区比对。允许真实几何、程序化材质、薄膜曲面、体积渐变、反射卡和受控合成。允许为固定视角采用艺术化方案，但必须记录做法及 Unity 替代方式，不能为了方便移植牺牲本阶段视觉目标。不加入计时器、音乐、提醒、按钮、菜单、岛屿、积分或文案。

2. 先锁定构图与识别关系
使用固定正视角、852×1846 竖屏；默认正交相机，若改为长焦透视需记录原因。水球中心约在画面横向50%、自顶向下52%～54%，静止主体直径约占屏宽62%，合理范围58%～68%。moving 的外部流带可以超出主体，但不能截断出画。顶部保留大面积留白。静止、运动共用相机、曝光、背景与主体身份，不能为两张图分别调出互不相容的光照。

3. still 静态造型
只有一个连续、近正圆的水球外轮廓。球内青绿色集中在中心，中心略深且边界逐渐散开，像水层向中心聚集，周围透明水膜被缓慢推开；不得做成硬边色块、独立内球、空心圆环或均匀染绿的实心珠。内部至少能辨认三种不同尺度的层次：宽而柔的中心色深、绕中心弯折的半透明水膜、膜边少量细薄折光。层次靠透射、曲率、厚度和遮挡形成，不靠叠加高亮白线。两点直径约为球直径2%～3%，一青绿、一克制暖霞光，处于相对平衡的位置；看起来悬在内部，不能像贴在镜头前的图标或发光珠。still 不出现外部流带。

4. moving 静态造型
将参考运动图当作被时间冻结的一帧。水球仍是同一个连续对象，轮廓局部缓慢隆起与收拢，中心位置稳定；默认局部径向变化约2%～6%，根据参考调整，不以整体缩放代替。青色中心更凝聚、更有深度，周围水层有被挤开、翻折与绕流的关系。水纹要有宽面、薄边、透光缝隙和前后遮挡，不能成为同心圆、几根等粗曲线或交叉塑料条。外部有两套开口的、宽窄变化的透明流带，大致沿主体左上和右下形成对向关系；青绿色占主导，暖色仅局部点缀。每个节点精确位于其对应路径端部，路径中段可展宽，尾部宽度与透明度同时趋零；不能硬切、组成完整圆环或脱离节点。静态阶段不宣称流带已经运动。

5. 材质与灯光
水感必须有可见证据：背景经过球体产生柔和折射变化；边缘有薄而连续、强弱变化的高光；内部水膜之间存在透叠和局部阴影；中心青色通过柔和透射深度表现。水的IOR可从1.333起步，但它是初始值，不是保真保证。禁止金属、厚玻璃弹珠、磨砂塑料、果冻、能量球或厚绿色壳。禁止中心出现白色圆形灯斑、花瓣状高光、径向尖点、明显噪点和锯齿。使用宽而长的柔光源或反射卡塑造带状高光，避免多个圆形面积灯的白斑占据主体。背景为浅灰白、极淡青灰、少量暖白的低对比柔和空间变化，不用天空、湖面或具象风景。moving 可增加极淡斜向暖光。记录实际渲染器、采样、降噪、曝光和色彩变换；渲染失败或回退必须明确报告，不能用输出文件名伪装渲染器。

6. Blender 实现约束
推荐先用 Cycles 确立透明、折射和层次；这是可调整的制作默认，不是强制指定某版本。单一封闭主体保持拓扑连续。内部采用开放的弯曲薄膜或程序化体积场，不用多个不同大小透明球套叠。局部形变必须在球面极点处连续，避免按经度直接形变导致极点尖锥和花瓣高光。高光优先来自材质与光照，不允许脱离形变的固定描边假装水球边缘。先做粗略构图渲染，再处理中心水层，再处理水膜与高光，最后调两点和外部流带；每轮明确只修正最大的一个视觉差距。保存可重现脚本、随机种子和参数，重复执行不得累积重复对象。

7. 静态验收与本阶段交付
交付可打开的 .blend、可重建脚本、参数文件、still.png、moving.png、两组参考与渲染的并排对比。保存两种状态预设，使用同一相机和同一主体拓扑；分别输出全画幅与主体细节比对，不能通过裁切掩盖尺寸错误。逐项检查：构图比例；外轮廓水感；中心青色聚集；内部膜层深度；波纹与光纹；两个点的位置与大小；moving 节点和两条流带的连续关系。每项写“通过/待修”和可见依据，不能用主观相似度百分比代替。若仍是灰色实心球、薄膜硬边贴纸、机械圆环、节点脱轨或尖点高光，继续修正静态画面，不进入动画。本阶段只提交静态结果等待视觉确认，不宣称产品交互完成。

8. 静态确认后的动画阶段（本次不执行）
保留 still / transitioning / moving 三种状态预设，以及独立 transition_progress、flow_time 和调试 reset。使用同一主体、相同材质和连续几何参数。still 仅允许极轻呼吸；transitioning 为0.8～1.2秒，依次表现两点获得向外速度、连续移向边缘、局部水滴扰动、节点释放与流带逐渐拉长；moving 持续局部形变、膜层移动和高光变化，两套流带速度略有差异且节点始终在其路径上。时间参数独立于帧率；不替换对象、不瞬移、不爆裂、不喷射，不靠旋转贴图或整体缩放假装水流。先做单次过渡和一段连续运动的预览，再检查每个中间帧。Blender 动画只能证明视觉连续性；点击命中、后台挂起与重复点击必须到 Unity 中另行验证。

9. Unity 移植依据（视觉与动画通过后执行）
导出统一的视觉参数表：画幅与球心、主体半径、局部形变公式/控制点/幅度/频率、两个点轨迹、流带中心线与截面宽度曲线、纵横向透明度、时间曲线、色彩空间、颜色、材质粗糙度与IOR、高光方向和宽度、折射强度与膜层深度。参数以主体半径R和秒为单位，颜色标记线性或sRGB；记录Blender到Unity的坐标轴变换。分类注明“可直接复用的几何/曲线/时间数据”“需要换算的相机参数”“需要重建与校准的Shader/灯光/色彩参数”。可导出网格和形态键，但不得承诺Blender材质节点、灯光瓦数、Cycles折射和合成节点一比一搬到Unity。给每个特殊光学效果提供Unity实现思路与降级方式，最终仍由Unity实时渲染；PNG和视频只作验收参考，不作最终动画背景。先用相同视角对齐Unity静态双状态，再接真实状态机、命中与动画测试；未经实机检查不得宣称移动端性能通过。
```
